# Wrocław Transit

Личное приложение для трамваев и автобусов Вроцлава под iPhone, **без своего сервера**:
расписание (GTFS) скачивается с портала Otwarte Dane Wrocław прямо на телефон, разбирается
в SQLite и дальше работает офлайн. Положения машин телефон запрашивает сам, пока открыта карта.

## Живая карта (этап 2)

- Карта Apple Maps (MapKit): без ключей и без стороннего сервера тайлов.
- Три источника опрашиваются раз в 10 секунд, каждый независимо от других:
  - MPK `POST mpk.wroc.pl/bus_position` — основной. Пробуются обе известные кодировки тела запроса,
    рабочая запоминается;
  - Open Data `open-data.cui.wroclaw.pl/hdb/db/14` — бортовой номер и бригада. Запись
    сопоставляется с ближайшей машиной той же линии в радиусе 250 м, неоднозначные пары не склеиваются;
  - Kłosok GTFS-RT `mapadlugoleka.klosok.eu/vehicle_positions.pb` — пригородные 9xx.
    Есть направление и опоздание. Для своих автобусов этот источник важнее двух других.
- Если источник упал, последний ответ остаётся на карте ещё 60–90 секунд, потом машины пропадают.
  На экране «Данные» видно, какой источник что вернул.
- Курс берётся из фида или из движения между опросами; у iMPK, пока машина не сдвинулась, —
  из маршрута к её конечной. Маркер — капля (вариант B): весь маркер вытянут туда, куда едет
  машина, номер стоит ровно. Форма одна для всех, тип — цветом: трамвай красный, автобус синий,
  экспресс фиолетовый, ночной тёмный. Пока курс неизвестен — круг без острия.
- Карту можно поворачивать двумя пальцами. Остриё капли доворачивается на угол карты (значки iOS сами
  не вращаются вместе с картой); раздвигание наложений тоже считается в повёрнутых координатах.
  Кнопка с красной стрелкой «N» появляется, когда карта повёрнута, и возвращает север вверх.
- Выбранная машина открывает панель на пол-экрана: направление, где она сейчас («на остановке…»,
  «проехал…»), следующая остановка с отсчётом, опоздание и сколько остановок осталось. Потянуть вверх (или
  нажать на ручку) — панель на весь экран со всеми остановками до конечной: время по расписанию и «через N мин»
  от реального положения; нажатие на остановку открывает её табло. Вниз с половины — закрыть. Если рейс по
  расписанию не найден, остановки показываются по маршруту, без времени. Центр карты сдвигается в свободную
  половину, машину под панелью карта поднимает.
- «Следить» (◎) в панели машины: камера плавно ведёт её по центру с каждой новой позицией (за те же 3 с,
  что и маркер). Перетаскивание карты в сторону выключает слежение, поворот — нет; другая машина или
  закрытая карточка тоже выключают.
- При отдалении машины становятся точками с затухающим хвостом (до 900 точек: весь город); выбранная остаётся с номером.
- Наложившиеся маркеры раздвигаются по кругу (до 6 в группе; очередь на конечной не трогается).
- Слой «Опоздания на карте» (кнопка слоёв): кольцо зелёное до 2 мин, жёлтое 2–5, красное больше 5,
  серое — рейс не определён.
- При нажатии на машину выбирается вариант маршрута — по расстоянию до линии и по курсу,
  потому что оба направления идут по одной улице. По варианту определяется направление,
  а на карте рисуются линия маршрута, остановки и следующая остановка. Нажатие на остановку открывает её табло.
- Фильтр линий сохраняется между запусками. Если в кадре больше 220 машин,
  приложение просит приблизить карту или выбрать линии.
- При сильном приближении на карте появляются остановки.
- Кнопки вверху — значки: «!» изменения в движении, слои карты, линии, шестерёнка — «Данные».
  Повторное нажатие, пока окно ещё открывается, второй раз его не открывает.

## Изменения в движении

Кнопка «!» на карте; число на ней — новые сообщения, которые ещё не открывались. Источник — карточки
сообщений на mpk.wroc.pl (главная и «Zmiany w komunikacji»): линии, срок действия, заголовок, а при
нажатии — полный текст со страницы сообщения. Это плановые изменения: объезды, ремонты, перенос остановок.
Внезапные сбои MPK публикует в X (@AlertMPK); без сервера их не прочитать, в окне есть ссылка.
Список обновляется раз в 30 минут, пока открыта карта, последний удачный хранится на телефоне.
Страница без блока сообщений — ошибка («сайт изменился»), а не «изменений нет».

## Задержки и рейсы (этап 3)

У фида MPK нет ни номера рейса, ни опоздания. Приложение определяет их на телефоне,
сопоставляя позицию машины с расписанием GTFS (перенос логики из MIT-версии,
`src/core/realtime/trip-match.ts`):

- позиция проецируется на геометрию маршрута → насколько машина продвинулась по рейсу;
- по расписанию это переводится в секунды от начала рейса;
- выбирается тот из рейсов этой формы, который сейчас был бы ровно здесь. Разница с
  расписанием — это опоздание; если ближайший рейс дальше 45 минут, рейс не угадывается.
- В карточке машины видно опоздание и время до следующей остановки.
- На табло остановки реальные рейсы накладываются на расписание по номеру рейса:
  у отслеживаемых сейчас машин показываются живой обратный отсчёт, опоздание и зелёная точка.

Kłosok отдаёт опоздание в своём GTFS-RT, поэтому для него оно берётся из фида.

## Избранное и напоминания

- Звёздочка на табло добавляет остановку в избранное; избранные — плашками на карте под поиском.
- Поиск без запроса показывает избранное и остановки в радиусе 800 м с расстоянием.
- Нажатие на рейс на табло — напоминание за 2, 5 или 10 минут локальным уведомлением.
  Пока табло открыто, напоминание сдвигается вместе с живой оценкой времени.
  Push-уведомления не используются, поэтому бесплатной подписи хватает.

## iMPK

API MPK (`https://impk.mpk.wroc.pl:8088/`), с разрешения MPK и по своему логину. Адрес, логин и
пароль вводятся на экране «Данные»; пароль хранится в Связке ключей iPhone, в коде и в репозитории
учётных данных нет. Пока iMPK выключен или не заполнен, он не запрашивается. Авторизация HTTP Digest
поверх обычного HTTPS с проверкой сертификата. Кнопка «Сохранить и проверить» показывает, что вернул
операцию из поля запроса (по умолчанию `getPositions`).

Когда iMPK включён и отвечает, карта показывает его машины: в нём все машины MPK с бортовым
номером, рейсом и опозданием. Позиции у MPK `bus_position` те же (сравнение: расхождение 0 м), поэтому
MPK при работающем iMPK опрашивается раз в минуту — для сравнения и как запасной; если iMPK молчит,
MPK сразу возвращается к опросу каждые 10 секунд. Сравнение — «Данные» → «Сравнение с iMPK»
(MPK — по линии и расстоянию до 400 м, Open Data — по бортовому номеру, с отставанием; номера
несовпавших машин), только по новым ответам. Лог за последний час — кнопка «Поделиться логом»;
хранится, пока приложение запущено.
Направление (конечная) — по коду słupka `d` из таблицы остановок расписания.
Табло остановки при включённом iMPK строится по `getPostInfo` каждого słupka: время по расписанию
iMPK, а если машина этого рейса (`c`) на карте — с её опозданием и зелёной точкой. Если iMPK
выключен или не ответил, табло — по расписанию GTFS, как раньше. Формат ответа —
`docs/impk-api.md`.

## Подложки карты

Выбор — кнопка слоёв на карте, ключи — в «Данных» (Связка ключей iPhone, в коде ключей нет). Подпись источника
внизу карты.

- Apple: приглушённая, стандарт, спутник, гибрид, 3D.
- Открытые: OpenStreetMap (только по запросу, без предзагрузки, кэш неделя — по правилам OSM),
  ÖPNVKarte с линиями транспорта (memomaps.de).
- С ключом: Thunderforest Transport (+ тёмная, Hobby — 150 000 плиток в месяц). CARTO и Stadia убраны.
- Аэрофото: ортофото Польши HD — GUGiK HighResolution через WMS. Его WMTS только в EPSG:2180/4326, а WMS
  перепроецирует GetMap в EPSG:3857, хотя в capabilities этого нет (проверено: во Вроцлаве совпадает со
  снимком 2024 пиксель в пиксель). Плитка собирается на сервере, 0,6–7 с. StandardResolution (WMTS) убран:
  старее и размытее. Поверх фото — названия улиц Apple.
- Вроцлав (SIP, gis.um.wroc.pl/portal_srv): готовые плитки в Web Mercator по стандартной схеме, до z21,
  {z}/{y}/{x}: ортофото 2024 с нанесёнными улицами и цветная карта города (обе — «brak ograniczeń»,
  с офлайном). За чертой города (404) у цветной карты видна карта Apple; ортофото её заменяет
  (иначе при каждом масштабе мелькал спутник Apple). Ортофото 2025 — временно, для теста, без офлайна. Ортофото 2024 из gis1 (OGC_ortofoto_2024) было пустым
  из‑за слоя: в WMS снимок — слой 1, не 0.
- Apple 3D: камера наклоняется на 60°, наклон двумя пальцами включён только в 3D.

### Офлайн

Только для подложек, чьи условия это разрешают: ортофото Польши HD (GUGiK, бесплатно для любых целей; регламент
Geoportal массовую загрузку ортофото не запрещает, в отличие от сервиса TOPO) и ортофото Вроцлава 2024
(без ограничений). Цветная карта города — тоже: на geoportal.wroclaw.pl/zasoby у «Podkładowa mapa Wrocławia» и
ортофото 2024 условия «brak ograniczeń». Ортофото 2025 разрешено только смотреть — без офлайна. OSM запрещает
предзагрузку, Thunderforest требует платный тариф, Google запрещает массовую загрузку.
Кнопка слоёв → «Офлайн»: весь Вроцлав или видимая область, масштабы 10…15–18 (весь город до 16 — около
5 000 плиток, ~125 МБ; до 17 — ~20 000, ~500 МБ). Плитки лежат в Documents/tiles/<подложка>/z/x/y — там же,
где кэш слоя карты, поэтому карта берёт их с телефона и не запрашивает снова (max age 0); вне пакета
плитки грузятся из сети. Загрузка по две плитки, продолжается с места остановки, ответы-не-картинки
(ошибки WMS) не сохраняются. Плитки исчезнувших подложек удаляются при запуске. Загрузка HD долгая
(сервер собирает каждую плитку): весь город до 16 — около часа.
- Google через Map Tiles API своим ключом (без Google Maps SDK): карта и рельеф; спутник и гибрид
  Google не отдаёт проектам с оплатой в ЕЭЗ (HTTP 403). Плитки Google не хранятся на телефоне.

Пока плитка нового масштаба грузится, MapKit оставляет на её месте пустой квадрат (серую сетку). Рендерер
слоя заменён (`patches/react-native-maps+1.29.11.patch`, применяется patch-package при `npm install`): пока
плитки нет, он рисует то, что уже лежит в кэше слоя для этого места на других масштабах — более мелкие
увеличенными, более крупные уменьшенными, — а потом резкая плитка заменяет картинку. Серое остаётся только там,
где на телефоне ещё ничего нет (первый просмотр места); с офлайн-пакетом его нет совсем. У Google кэша нет —
его плитки на телефоне не хранятся.

## Живые источники

iMPK и Kłosok опрашиваются каждые 10 секунд; MPK — каждые 10 секунд, а пока отвечает iMPK, раз в минуту.
Open Data — запасной: опрашивается раз в минуту, только когда ни iMPK, ни MPK не отвечали последние
30 секунд (его таблица обычно отстаёт на 11 минут и пуста после отсева, в лучшем случае — на полторы).
Источник с ошибкой ждёт 30 с, потом 60, 120 … до 5 минут; его последний хороший ответ остаётся на карте.

## Расписание (этапы 0–1)

- Поиск снимка GTFS на портале города: выбирается снимок, **действующий сегодня**, а не
  самый новый. В архиве города лежат расписания с будущей датой начала. Неполные снимки
  (без `shapes.txt`) отбрасываются и больше не скачиваются.
- Потоковый импорт: zip читается частями, ~1 млн строк `stop_times` пишутся в SQLite
  пачками. Старая база работает, пока строится новая, и заменяется только после успешного импорта.
- Поиск остановок без учёта диакритики («swid» → «Świdnicka»), с линиями на каждой остановке.
- Табло отправлений по расписанию по всем słupkам остановки или по одному. Учитываются
  ночные рейсы прошлого служебного дня (25:30), отмены по `calendar_dates` и переход на
  летнее/зимнее время. Прибытие на конечную не считается отправлением.
- Проверка обновления не чаще раза в 12 часов при открытии приложения, ручная — на экране «Данные».

Следующие этапы: живое табло на остановках для машин MPK (сделано ниже), избранное.

## Разработка

```bash
npm ci
npm test            # ядро: импорт, запросы, выбор снимка — без сети, на фикстурах
npm run typecheck
npx expo lint
npx expo start      # нужен dev build: npx expo run:ios / run:android
```

Ядро (`src/core`) не зависит от React Native и тестируется в Node: база в тестах — sql.js,
в приложении — expo-sqlite, обе через интерфейс `Db` (`src/core/db.ts`).

```
src/
  app/              экраны (expo-router): карта, поиск, табло остановки, линии, данные
  core/
    gtfs/           catalogue (поиск снимка), zip/csv (потоковое чтение), importer, queries, map-queries, update
    realtime/       mpk, open-data, gtfs-rt (свой декодер), klosok, tracker (слияние), route-match
    geo.ts          расстояния, курс, проекция на линию маршрута
    net/http.ts     fetch с таймаутом на весь обмен, включая чтение тела
    time/warsaw.ts  время Вроцлава без Intl (правило ЕС для летнего времени)
  platform/         expo-sqlite, файлы, жизненный цикл базы расписания
  state/            zustand
  ui/               тема, бейджи линий, баннер статуса
test/               jest + sql.js, фикстура GTFS собирается в памяти
```

## Сборка и установка без Mac и без платного Apple-аккаунта

Сборка идёт в GitHub Actions (`.github/workflows/ci.yml`). На каждый push запускаются
lint, typecheck и тесты. `.ipa` собирается только по тегу `v*` или вручную
(Actions → CI → Run workflow), потому что минуты macOS дорогие.

- **iOS**: артефакт `wroclaw-transit-ios-unsigned` содержит `WroclawTransit-unsigned.ipa`.
  Подпишите его своим Apple ID в **Sideloadly** или **AltStore** и установите на iPhone.
  Бесплатная подпись живёт 7 дней. AltStore продлевает её сам, если на компьютере в той же
  Wi-Fi-сети запущен AltServer. Приложению не нужны push-уведомления и App Groups,
  поэтому бесплатного аккаунта достаточно.
`ios/` генерируется командой `expo prebuild` и в git не хранится. Приложение только под iOS.
