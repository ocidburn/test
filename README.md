# Wrocław Transit

Личное приложение для трамваев и автобусов Вроцлава под iPhone, **без своего сервера**:
расписание (GTFS) скачивается с портала Otwarte Dane Wrocław прямо на телефон, разбирается
в SQLite и дальше работает офлайн. Положения машин телефон запрашивает сам, пока открыта карта.

## Живая карта (этап 2)

- Карта Apple Maps (MapKit): без ключей и без стороннего сервера тайлов.
- Три источника опрашиваются раз в 10 секунд, каждый независимо от других:
  - MPK `POST mpk.wroc.pl/bus_position` — основной. Пробуются обе известные кодировки тела запроса,
    рабочая запоминается;
  - Open Data `open-data.cui.wroclaw.pl/hdb/db/14` — бортовой номер и бригада. Запись
    сопоставляется с ближайшей машиной той же линии в радиусе 250 м, неоднозначные пары не склеиваются;
  - Kłosok GTFS-RT `mapadlugoleka.klosok.eu/vehicle_positions.pb` — пригородные 9xx.
    Есть направление и опоздание. Для своих автобусов этот источник важнее двух других.
- Если источник упал, последний ответ остаётся на карте ещё 60–90 секунд, потом машины пропадают.
  На экране «Данные» видно, какой источник что вернул.
- Курс берётся из фида или из движения между опросами. Маркер — «капля»: остриё показывает,
  куда едет машина, форма тела — тип: скруглённый квадрат — трамвай, круг — автобус,
  ромб — экспресс, пунктирный край — пригородный, светлый край на тёмном — ночной.
- При отдалении машины становятся точками с хвостом; выбранная остаётся с номером.
- Наложившиеся маркеры раздвигаются по кругу (до 6 в группе; очередь на конечной не трогается).
- Слой «Опоздания на карте» (экран «Линии»): кольцо зелёное до 2 мин, жёлтое 2–5, красное больше 5.
  Без кольца — рейс не определён.
- При нажатии на машину выбирается вариант маршрута — по расстоянию до линии и по курсу,
  потому что оба направления идут по одной улице. По варианту определяется направление,
  а на карте рисуются линия маршрута, остановки и следующая остановка. Нажатие на остановку открывает её табло.
- Фильтр линий сохраняется между запусками. Если в кадре больше 220 машин,
  приложение просит приблизить карту или выбрать линии.
- При сильном приближении на карте появляются остановки.

## Задержки и рейсы (этап 3)

У фида MPK нет ни номера рейса, ни опоздания. Приложение определяет их на телефоне,
сопоставляя позицию машины с расписанием GTFS (перенос логики из MIT-версии,
`src/core/realtime/trip-match.ts`):

- позиция проецируется на геометрию маршрута → насколько машина продвинулась по рейсу;
- по расписанию это переводится в секунды от начала рейса;
- выбирается тот из рейсов этой формы, который сейчас был бы ровно здесь. Разница с
  расписанием — это опоздание; если ближайший рейс дальше 45 минут, рейс не угадывается.
- В карточке машины видно опоздание и время до следующей остановки.
- На табло остановки реальные рейсы накладываются на расписание по номеру рейса:
  у отслеживаемых сейчас машин показываются живой обратный отсчёт, опоздание и зелёная точка.

Kłosok отдаёт опоздание в своём GTFS-RT, поэтому для него оно берётся из фида.

## Избранное и напоминания

- Звёздочка на табло добавляет остановку в избранное; избранные — плашками на карте под поиском.
- Поиск без запроса показывает избранное и остановки в радиусе 800 м с расстоянием.
- Нажатие на рейс на табло — напоминание за 2, 5 или 10 минут локальным уведомлением.
  Пока табло открыто, напоминание сдвигается вместе с живой оценкой времени.
  Push-уведомления не используются, поэтому бесплатной подписи хватает.

## iMPK

API MPK (`https://impk.mpk.wroc.pl:8088/`), с разрешения MPK и по своему логину. Адрес, логин и
пароль вводятся на экране «Данные»; пароль хранится в Связке ключей iPhone, в коде и в репозитории
учётных данных нет. Пока iMPK выключен или не заполнен, он не запрашивается. Авторизация HTTP Digest
поверх обычного HTTPS с проверкой сертификата. Кнопка «Сохранить и проверить» показывает, что вернул
операцию из поля запроса (по умолчанию `getPositions`).

Когда iMPK включён и отвечает, он заменяет MPK `bus_position` и Open Data: в нём все машины MPK
с бортовым номером и опозданием. Те два источника не опрашиваются, пока iMPK ответил за последние
30 секунд; если он замолчал, его последний ответ держится минуту, а MPK и Open Data возвращаются.
Направление (конечная) — по коду słupka `d` из таблицы остановок расписания. Формат ответа —
`docs/impk-api.md`.

## Живые источники

MPK и Kłosok опрашиваются каждые 10 секунд, Open Data — раз в минуту (таблица большая и
отстаёт на несколько минут). Источник с ошибкой ждёт 30 с, потом 60, 120 … до 5 минут;
его последний хороший ответ остаётся на карте.

## Расписание (этапы 0–1)

- Поиск снимка GTFS на портале города: выбирается снимок, **действующий сегодня**, а не
  самый новый. В архиве города лежат расписания с будущей датой начала. Неполные снимки
  (без `shapes.txt`) отбрасываются и больше не скачиваются.
- Потоковый импорт: zip читается частями, ~1 млн строк `stop_times` пишутся в SQLite
  пачками. Старая база работает, пока строится новая, и заменяется только после успешного импорта.
- Поиск остановок без учёта диакритики («swid» → «Świdnicka»), с линиями на каждой остановке.
- Табло отправлений по расписанию по всем słupkам остановки или по одному. Учитываются
  ночные рейсы прошлого служебного дня (25:30), отмены по `calendar_dates` и переход на
  летнее/зимнее время. Прибытие на конечную не считается отправлением.
- Проверка обновления не чаще раза в 12 часов при открытии приложения, ручная — на экране «Данные».

Следующие этапы: живое табло на остановках для машин MPK (сделано ниже), избранное.

## Разработка

```bash
npm ci
npm test            # ядро: импорт, запросы, выбор снимка — без сети, на фикстурах
npm run typecheck
npx expo lint
npx expo start      # нужен dev build: npx expo run:ios / run:android
```

Ядро (`src/core`) не зависит от React Native и тестируется в Node: база в тестах — sql.js,
в приложении — expo-sqlite, обе через интерфейс `Db` (`src/core/db.ts`).

```
src/
  app/              экраны (expo-router): карта, поиск, табло остановки, линии, данные
  core/
    gtfs/           catalogue (поиск снимка), zip/csv (потоковое чтение), importer, queries, map-queries, update
    realtime/       mpk, open-data, gtfs-rt (свой декодер), klosok, tracker (слияние), route-match
    geo.ts          расстояния, курс, проекция на линию маршрута
    net/http.ts     fetch с таймаутом на весь обмен, включая чтение тела
    time/warsaw.ts  время Вроцлава без Intl (правило ЕС для летнего времени)
  platform/         expo-sqlite, файлы, жизненный цикл базы расписания
  state/            zustand
  ui/               тема, бейджи линий, баннер статуса
test/               jest + sql.js, фикстура GTFS собирается в памяти
```

## Сборка и установка без Mac и без платного Apple-аккаунта

Сборка идёт в GitHub Actions (`.github/workflows/ci.yml`). На каждый push запускаются
lint, typecheck и тесты. `.ipa` собирается только по тегу `v*` или вручную
(Actions → CI → Run workflow), потому что минуты macOS дорогие.

- **iOS**: артефакт `wroclaw-transit-ios-unsigned` содержит `WroclawTransit-unsigned.ipa`.
  Подпишите его своим Apple ID в **Sideloadly** или **AltStore** и установите на iPhone.
  Бесплатная подпись живёт 7 дней. AltStore продлевает её сам, если на компьютере в той же
  Wi-Fi-сети запущен AltServer. Приложению не нужны push-уведомления и App Groups,
  поэтому бесплатного аккаунта достаточно.
`ios/` генерируется командой `expo prebuild` и в git не хранится. Приложение только под iOS.
